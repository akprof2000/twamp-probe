SPI TWamp Probe — проба системы SPI TWamp
=========================================

Что это
-------
Агент, выполняющий замеры по заданиям сервера. Один статический бинарник ~6 МБ
без зависимостей: не нужен ни .NET, ни какие-либо библиотеки — работает на любом
Linux x86-64, включая CentOS 7/8/9, Rocky, Alma, Ubuntu, Debian.

Работает с сервером SPI.Twamp.Server: эндпоинты api/probeinterface, доставка
результатов с подтверждением (ACK), инкрементальное слияние задач и
cron-расписания. Версия пробы видна в списке проб на сервере.

Состав папки
------------
  twamp-probe        — исполняемый файл (Linux x86-64, статический)
  twping             — зонд TWAMP из пакета perfSONAR (el7, работает с CentOS 7)
  appsettings.json   — конфигурация
  twampy/            — вендоренный nokia/twampy для режима TWampy
  install-centos.sh  — установка на CentOS/RHEL со всеми настройками
  twamp-probe.service— юнит systemd с поднятыми лимитами
  99-twamp-probe.conf— настройки ядра (кладётся в /etc/sysctl.d/)
  README-DEPLOY.txt  — этот файл

Установка на CentOS / RHEL (рекомендуемая)
-----------------------------------------
1. Скопируйте папку на машину и запустите установщик от root:
     scp -r twamp-probe-go root@host:/tmp/
     ssh root@host 'cd /tmp/twamp-probe-go && ./install-centos.sh'

   Он положит пробу в /opt/twamp-probe-go, применит настройки ядра и
   поставит службу systemd с поднятыми лимитами. Повторный запуск безопасен:
   ваш appsettings.json не затирается.

2. На сервере: «Статус проб» → «Опросить пробу» (http://адрес:8443) →
   «Подтвердить». Дальше всё как с обычной пробой.

Установка вручную (любой Linux)
-------------------------------
1. Скопируйте папку, например в /opt/twamp-probe-go, и дайте права:
     chmod +x /opt/twamp-probe-go/twamp-probe /opt/twamp-probe-go/twping

2. Запустите (порт по умолчанию 8443 — root не нужен):
     cd /opt/twamp-probe-go && ./twamp-probe
   Порт меняется в appsettings.json ("Urls").

Почему важны лимиты (и что будет без них)
-----------------------------------------
Один идущий замер стоит ядру ДВУХ учётных единиц: процесса зонда (twping,
python -m twampy, ping) и потока пробы, который ждёт его завершения.
Проверено: на 1500 запущенных зондов у пробы 1523 потока.

Обе единицы считаются в ulimit -u, а в CentOS/RHEL он по умолчанию равен
4096 (файл /etc/security/limits.d/20-nproc.conf) — это граница ровно в 2048
одновременных замеров. За ней ядро отказывает в создании потока, и для Go
это fatal error: перехватить нельзя, служба умирает целиком.

Проба это заметит и предупредит при старте, но настройку не изменит:

  WARN Система может не выдержать настроенное число замеров настроено=100000
       причина="лимит процессов и потоков пользователя (ulimit -u) = 4096,
       а на 100000 одновременных замеров внешними утилитами нужно ~200000..."

Сама она поднимает мягкий ulimit -u до жёсткого и предел потоков Go; лимиты
службы и ядра поднять можете только вы — это и делает install-centos.sh.

Встроенных зондов ("embedded" ниже) всё это не касается вовсе: они не занимают
ни процесса, ни потока.

Режимы зондирования
-------------------
  WinPing — системный ping (аргументы по умолчанию "-c 2" — Linux-синтаксис);
  TWamp   — два пути на выбор:
            * внешняя утилита twping: уже лежит в папке (linux-пакет), ставить
              ничего не нужно. Это бинарник из релизного пакета perfSONAR для
              el7, поэтому работает начиная с CentOS 7. Свою версию можно
              подставить через "twamp:name" в appsettings.json;
            * встроенный клиент: "twamp": { "embedded": true }. Внешняя утилита
              не запускается, замер не занимает ни процесса, ни потока — предел
              из раздела про лимиты на такие замеры НЕ действует. Используется
              библиотека twping-go, та же, из которой собрана сама утилита,
              поэтому вывод совпадает;
  TWampy  — два пути на выбор:
            * внешний python: нужен Python 3.8+ в PATH, пакет twampy уже
              в папке, PYTHONPATH проба выставляет сама;
            * встроенный отправитель: "twampy": { "embedded": true }
              в appsettings.json. Python не нужен вовсе, а замер не занимает
              ни процесса, ни потока — предел из раздела про лимиты на такие
              замеры НЕ действует. Значения совпадают с оригиналом
              (сверка: roundtrip 401 мкс у python против 403 мкс встроенного).

Локальные порты зондов
----------------------
Порт для каждого замера проба выдаёт сама из диапазона Probe:PortRange
(по умолчанию 20000-32767). Так два замера не берут один порт, а когда
свободных нет — замер ждёт освобождения, а не падает.

Пул общий для TWamp и TWampy: twping и twampy берут номера из одного
диапазона под общим замком и за порты друг с другом не конкурируют.
Управляющее соединение twping идёт по TCP и пул не расходует —
пространства портов TCP и UDP у ядра разные.

При старте проба сверяет пул с ip_local_port_range и предупреждает в
журнале, если диапазоны пересекаются.

ВАЖНО: диапазон обязан быть зарезервирован в ядре. Настройка
99-twamp-probe.conf расширяет эфемерный диапазон (ip_local_port_range =
1024 65535), и без резервирования он накрывает пул пробы: ядро отдаёт наши
номера чужим соединениям, и замеры падают с "address already in use" —
на законно выданных портах. Поэтому в том же файле есть строка:

  net.ipv4.ip_local_reserved_ports = 20000-32767

Она обязана совпадать с Probe:PortRange. Меняете одно — меняйте и второе.

install-centos.sh применяет это сам. Если ставили вручную, проверьте:

  cat /proc/sys/net/ipv4/ip_local_reserved_ports    # должен показать диапазон
  sudo sysctl --system                              # применить, если пусто

Если в журнале всё же появляется "Порт занят посторонним процессом" — значит
внутри диапазона слушает какая-то служба. Проба уведёт такой порт в карантин
на 5 минут и повторит замер на другом (до десяти попыток), после чего порт
вернётся в оборот сам. Но лучше найти виновника:

  ss -lunp | awk '$5 ~ /:(2[0-9]{4}|3[0-2][0-9]{3})$/'

systemd вручную (если не пользуетесь install-centos.sh)
------------------------------------------------------
Готовый юнит лежит рядом — twamp-probe.service; в нём уже прописаны лимиты:

  cp twamp-probe.service /etc/systemd/system/
  cp 99-twamp-probe.conf /etc/sysctl.d/ && sysctl --system
  systemctl daemon-reload && systemctl enable --now twamp-probe

Ключевые строки юнита — LimitNPROC=65535 и LimitNOFILE=1048576.
Проверить, что лимиты применились:

  grep -E 'Max processes|Max open files' /proc/$(systemctl show -p MainPID --value twamp-probe)/limits

Файлы, создаваемые при работе
-----------------------------
  TaskInfo.json   — реестр задач по расписанию (переживает перезапуск)
  JobResult.json  — недоставленные результаты (переживают перезапуск)

Особенности
-----------
  - логи пишутся в файл с ротацией и в stdout (journald при запуске службой);
  - Swagger на пробе нет; статус задач сервер получает через прокси
    probetaskstatus — в веб-интерфейсе он виден;
  - статистика выполнения (TaskStatus) обнуляется при перезапуске.
